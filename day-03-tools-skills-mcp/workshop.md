## Workshop 5 · Research & Computer Agent
**20:30 – 21:10 น. · 40 นาที**

หนึ่งโจทย์ เดินครบทุกขั้น โดยให้ Agent ใช้ Search, File System และ Terminal ในงานเดียวกัน
ปลายทางคือไฟล์ `report.md` ที่เปิดอ่านได้จริง ไม่ใช่ข้อความในแชท

### เลือกหนึ่งเส้น
ทุกเส้นใช้เครื่องมือชุดเดียวกัน และจบที่ไฟล์ Report หนึ่งไฟล์เหมือนกัน

| | เส้น A · คู่แข่งและตลาด | เส้น B · ข้อมูลในเครื่องเรา | เส้น C · งานประจำที่ทำซ้ำ |
|---|---|---|---|
| ใช้อะไร | คู่แข่งหรือสินค้าหนึ่งตัวที่เกี่ยวกับงานเรา | ไฟล์งานจริงที่มีอยู่แล้ว — csv, log, เอกสาร | งานที่เราทำเองอยู่ทุกสัปดาห์ |
| 1 | ค้นข้อมูลล่าสุด 5 แหล่ง | ให้ Agent สำรวจโครงสร้างก่อน | อธิบายขั้นตอนที่เราทำ |
| 2 | สรุปจุดแข็ง–จุดอ่อน | ถามคำถามที่ตอบได้จากข้อมูล | ให้ Agent ทำแล้วเทียบผล |
| 3 | เสนอ 3 ข้อที่เราทำได้ | สรุปพร้อมตัวเลขอ้างอิง | บันทึกจุดที่ต้องแก้ |

> เลือกภายใน 2 นาทีแล้วเริ่มเลย — เส้นไหนก็ได้ ขอให้เป็นเรื่องที่เราสนใจจริง งานจะเดินเร็วกว่ามาก

### Prompt ตั้งต้น — คัดลอกไปใช้ได้เลย
เปลี่ยนเฉพาะข้อความในวงเล็บ ที่เหลือปล่อยไว้ตามนี้

```text
ทำงานอยู่ในโฟลเดอร์ day3-workshop เท่านั้น

โจทย์: [เขียนโจทย์ของเส้นที่เลือก 1–2 บรรทัด]

ขอให้ทำตามนี้
1. สรุปโจทย์เป็นแผนย่อยให้ผมอ่านก่อน แล้วรอผมตอบ ok
2. ค้นและอ่านข้อมูลจริง อย่าตอบจากความจำ
3. บอกทุกครั้งว่าใช้เครื่องมืออะไร และได้อะไรกลับมา
4. เขียนผลลงไฟล์ report.md ในโฟลเดอร์นี้
5. ปิดท้ายด้วยรายการแหล่งที่มา และสิ่งที่ยังไม่แน่ใจ

ถ้าจะลบหรือเขียนทับไฟล์เดิม ให้ถามผมก่อนเสมอ
```

| บรรทัด | ทำไมต้องมี |
|---|---|
| ขอบเขต | กันไม่ให้ Agent เดินออกไปแตะไฟล์อื่นในเครื่อง |
| รอ ok | ได้เห็นแผนก่อนเสียเวลา 20 นาทีไปกับแผนที่ผิด |
| ห้ามตอบจากความจำ | บังคับให้เรียกเครื่องมือจริง ไม่ใช่เดาแล้วเขียนสวย |
| รายงานเครื่องมือ | ทำให้เราตรวจย้อนได้ว่าข้อสรุปมาจากไหน |
| เขียนลงไฟล์ | ผลงานอยู่นอกแชท เอาไปใช้ต่อและส่งต่อได้ |
| บอกสิ่งที่ไม่แน่ใจ | ลดการเติมเต็มช่องว่างด้วยข้อความที่ฟังดูดี |

> Prompt ที่ดีคือ **สัญญาว่าจะส่งอะไรกลับ** ไม่ใช่คำอธิบายว่าอยากได้อะไรสวย ๆ

### ติดตรงนี้ · ทำแบบนี้

| ปัญหา | ทางแก้ |
|---|---|

## Workshop 6 · Build Your Own Skill
**21:40 – 21:55 น. · 15 นาที**

เลือกงานที่ตัวเองทำซ้ำอยู่แล้วหนึ่งงาน แล้วเปลี่ยนให้เป็น Skill ที่เรียกใช้ได้

| # | ขั้น | เวลา | หมายเหตุ |
|---|---|---|---|
| 01 | เลือก Use Case จากงานประจำที่ทำซ้ำอย่างน้อยสัปดาห์ละครั้ง | 2 นาที | งานที่น่าเบื่อที่สุดคือ Skill แรกที่คุ้มที่สุด |
| 02 | เขียน Input / Process / Output ให้ครบก่อนลงมือ | 6 นาที | เขียน Output ก่อน แล้วย้อนกลับมาเขียน Process |
| 03 | สร้าง Skill แล้วให้ Agent ทำงานตามโดยไม่ต้องอธิบายเพิ่ม | 4 นาที | ถ้ายังต้องอธิบายเพิ่ม แปลว่ามีบรรทัดที่ยังขาด |
| 04 | ทดสอบซ้ำด้วยข้อมูลชุดใหม่ แล้วแก้ Skill จากผลที่ได้ | 3 นาที | ชุดใหม่คือชุดที่ Skill ยังไม่เคยเห็น |

> จบ 15 นาทีแล้วต้องมีไฟล์ `SKILL.md` หนึ่งไฟล์ ที่เรียกแล้วทำงานได้จริงอย่างน้อยหนึ่งรอบ

### เลือก Use Case ใน 2 นาที

| # | คำถาม | เกณฑ์ |
|---|---|---|
| 01 | งานอะไรที่เราทำซ้ำทุกสัปดาห์ แล้วไม่ค่อยอยากทำ | ตัวอย่าง · สรุปประชุม · เช็ก log เมื่อคืน · ทำรายงานยอด · ตอบอีเมลรูปแบบเดิม |
| 02 | ถ้าเราสอนเพื่อนร่วมงานคนใหม่ จะบอกเป็นกี่ขั้น | 3–6 ขั้น กำลังดี · เกิน 10 ขั้น ให้ตัดเหลือเฉพาะส่วนที่ซ้ำจริง |
| 03 | งานนี้ “เสร็จ” หน้าตาเป็นยังไง | ไฟล์อะไร เก็บไว้ที่ไหน มีหัวข้ออะไรบ้าง — ถ้าตอบไม่ได้ ยังเขียน Output ไม่ได้ |

> ตัน 2 นาทีแล้วยังไม่ได้ ให้หยิบงานที่เพิ่งทำใน Workshop 5 มาทำเป็น Skill เลย — นั่นคือทางลัดที่ตั้งใจไว้

### เทมเพลต — เติมช่องว่างแล้วใช้ได้เลย
ฉบับเต็มอยู่ที่ [`templates/SKILL.md`](../templates/SKILL.md)

```markdown
---
name: ________-________
description: ทำ ________ ให้ ________
  ใช้เมื่อผู้ใช้พูดว่า "________"
---

## Input
- ต้องมี ________ ก่อนเริ่ม
- อยู่ที่ ________
- ถ้าไม่มี ให้ ________ แทนการเดา

## Process
1. ________
2. ________
3. ถ้า ________ ให้ ________
4. ห้าม ________

## Output
- ไฟล์ ________ เก็บที่ ________
- มีหัวข้อ ________ และ ________
- ถือว่าเสร็จเมื่อ ________
```

ตัวอย่างที่เติมแล้ว · `name: meeting-notes` · ต้องมี *บันทึกเสียงหรือโน้ตดิบ* ก่อนเริ่ม · `3. ถ้าไม่มีผู้รับผิดชอบ ให้ถามก่อน` · ไฟล์ `notes/YYYY-MM-DD.md`

### ทดสอบ Skill ของตัวเอง · สามรอบ
เขียนเสร็จยังไม่นับ — ผ่านสามรอบนี้แล้วค่อยเรียกว่าใช้งานได้

| รอบ | ทำอะไร | ✓ ผ่านเมื่อ | ✕ ไม่ผ่านแล้วแก้ตรงไหน |
|---|---|---|---|
| 1 · เรียกตรง ๆ | บอกชื่อ Skill แล้วสั่งให้ทำ | ทำครบทุกขั้นโดยเราไม่ต้องเสริมอะไรเลย | ถ้ายังต้องเสริม แปลว่า Process ยังไม่ครบ |
| 2 · เรียกด้วยภาษาคน | พิมพ์ประโยคที่จะพูดจริงในวันทำงาน ไม่บอกชื่อ Skill | Agent หยิบ Skill ขึ้นมาเอง | ถ้าไม่หยิบ ให้ไปแก้ `description` |
| 3 · ป้อนข้อมูลไม่ครบ | จงใจไม่ให้ไฟล์ หรือให้ไฟล์ผิดรูปแบบ | มันถามกลับ แทนที่จะเดาแล้วทำต่อ | ถ้าเดา ให้เพิ่มเงื่อนไขในส่วน Input |

> **รอบที่ 2 คือรอบที่คนตกมากที่สุด** — Skill ที่เรียกไม่ติด เท่ากับไม่มี Skill
