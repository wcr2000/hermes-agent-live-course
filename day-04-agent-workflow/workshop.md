## Workshop 7 · Build Agent Workflow
**20:30 – 21:15 น. · 45 นาที**

หนึ่งโจทย์ เดินครบเจ็ดขั้น โดยให้ Agent หยุดให้เราตรวจที่ขั้น 2 และขั้น 6
ปลายทางคือไฟล์ผลงานที่เปิดอ่านได้จริง ไม่ใช่ข้อความในแชท

```
1 เข้าใจโจทย์ → 2 วางแผน → 3 ค้นและอ่าน → 4 วิเคราะห์ → 5 ลงมือทำ → 6 ตรวจสอบ → 7 ส่งผลงาน
      3′            7′            10′           7′           10′          8′
                     ▲ หยุดให้ตรวจ                                ▲ หยุดให้ตรวจ
```

### เลือกหนึ่งเส้น
ทุกเส้นเดินครบเจ็ดขั้นเหมือนกัน และจบที่ไฟล์ผลงานหนึ่งไฟล์เหมือนกัน

| | เส้น A · งานวิจัยและสรุป | เส้น B · งานข้อมูลในเครื่อง | เส้น C · งานประจำหลายขั้น |
|---|---|---|---|
| ใช้อะไร | เรื่องที่ต้องหาข้อมูลจากหลายแหล่งแล้วสรุปให้คนอื่นอ่าน | ไฟล์งานจริงที่มีอยู่แล้ว — csv, log, เอกสารเก่าของทีม | งานที่เราทำเองทุกสัปดาห์แล้วใช้เวลานาน |
| 1 | ค้นอย่างน้อย 5 แหล่ง | สำรวจโครงสร้างก่อน | เขียนขั้นตอนที่ทำจริง |
| 2 | เทียบและตัดที่ไม่เกี่ยว | ตั้งคำถามที่ตอบได้จริง | ให้ Agent เดินตามทีละขั้น |
| 3 | สรุปหนึ่งหน้าพร้อมที่มา | รายงานพร้อมตัวเลขอ้างอิง | จดจุดที่มันหลุดจากขั้น |

> เลือกภายใน 2 นาทีแล้วเริ่มเลย — โจทย์ที่เราสนใจจริงจะเดินเร็วกว่าโจทย์ที่ฟังดูดี

### Prompt ตั้งต้น — คัดลอกไปใช้ได้เลย

```text
ทำงานอยู่ในโฟลเดอร์ day4-workshop เท่านั้น

โจทย์ใหญ่: [เขียนโจทย์ของเส้นที่เลือก 1–2 บรรทัด]

ให้ทำตาม Workflow นี้ ทีละขั้น อย่าข้าม
1. เข้าใจโจทย์ — ถามกลับถ้ามีอะไรกำกวม
2. วางแผน — แตกเป็น 4–7 ขั้น แล้วรอผมตอบ ok
3. ค้น/อ่าน — ใช้เครื่องมือจริง บันทึกแหล่งที่มาทุกครั้ง
4. วิเคราะห์ — ตัดสิ่งที่ไม่เกี่ยวกับโจทย์ออก
5. ลงมือ — เขียนผลลงไฟล์ในโฟลเดอร์นี้
6. ตรวจสอบ — สุ่มตรวจข้ออ้าง 2 ข้อย้อนกลับไปหาแหล่ง
7. ส่งผล — สรุปสิ่งที่ทำ ไฟล์ที่ได้ และสิ่งที่ยังไม่แน่ใจ

จบทุกขั้น ให้บอกว่าใช้เครื่องมืออะไรและได้ไฟล์อะไร
ถ้าขั้นไหนล้ม ให้หยุดแล้วรายงาน อย่าเดาต่อ
```

| บรรทัด | ทำไมต้องมี |
|---|---|
| ขอบเขต | กันไม่ให้ Agent เดินออกไปแตะไฟล์อื่นในเครื่อง |
| รอ ok ที่ขั้น 2 | ได้เห็นแผนก่อนเสียเวลา 30 นาทีไปกับแผนที่ผิด |
| บันทึกแหล่งที่มา | ทำให้ขั้นตรวจสอบมีของให้ตรวจจริง ไม่ใช่ตรวจความรู้สึก |
| เขียนลงไฟล์ | ขั้นถัดไปอ่านจากไฟล์ได้ Context จึงไม่บวมจนลืมโจทย์ |
| สุ่มตรวจ 2 ข้อ | เปลี่ยนจาก “ดูน่าเชื่อ” เป็น “ตรวจแล้วตรง” |
| ล้มแล้วให้หยุด | กันการเดาต่อเงียบ ๆ ซึ่งเป็นความผิดพลาดที่แพงที่สุด |

> Prompt ที่ดีคือ **สัญญาว่าจะส่งอะไรกลับในแต่ละขั้น** ไม่ใช่คำอธิบายว่าอยากได้อะไรสวย ๆ

### เดินทีละขั้น · ขั้นที่ 1 ถึง 3 (นาทีที่ 0 – 20)

| # | ขั้น | สิ่งที่เราพิมพ์ | ต้องเห็น | ถ้าไม่ตรง |
|---|---|---|---|---|
| 01 | **เข้าใจโจทย์ · 3 นาที** | วางโจทย์ใหญ่ แล้วให้ Agent ถามกลับก่อนว่ามีอะไรกำกวม | คำถามกลับที่ตรงจุด ไม่ใช่ “รับทราบครับ เริ่มเลยนะครับ” | ถ้ามันไม่ถามอะไรเลย แปลว่ามันกำลังจะเดา |
| 02 | **วางแผน · 7 นาที** | ให้แตกเป็น 4–7 ขั้น พร้อมบอกว่าแต่ละขั้นจะได้ไฟล์อะไร | แผนเป็นข้อ ๆ ที่ระบุผลลัพธ์ของแต่ละขั้นไว้ชัด | ขั้นไหนไม่มีผลลัพธ์ ให้สั่งรวบกับขั้นข้าง ๆ |
| 03 | **ค้นและอ่าน · 10 นาที** | ให้ใช้เครื่องมือจริง แล้วเขียนผลลง `research.md` พร้อมแหล่งที่มา | ไฟล์จริงในโฟลเดอร์ ที่มีลิงก์หรือชื่อไฟล์กำกับทุกข้อ | เจอสรุปที่ไม่มีที่มา ให้ถามกลับว่า “อันนี้มาจากไหน” |

> จับเวลาจริง — เกินเวลาให้ตัดขอบเขตโจทย์ลง อย่ายืดเวลา เพราะยังเหลืออีกสี่ขั้น

| # | ขั้น | สิ่งที่เราพิมพ์ | ต้องเห็น | ถ้าไม่ตรง |
|---|---|---|---|---|
| 04 | **วิเคราะห์ · 7 นาที** | ให้เทียบข้อมูลที่ได้ แล้วตัดสิ่งที่ไม่ตอบโจทย์ทิ้ง | สิ่งที่ถูกตัดออก พร้อมเหตุผลสั้น ๆ ว่าตัดเพราะอะไร | ถ้าไม่มีอะไรถูกตัดเลย แปลว่ายังไม่ได้วิเคราะห์ |

## Workshop 8 · AI Team Architecture
**21:45 – 22:00 น. · 15 นาที**

เอา Workflow จาก Workshop 7 มาแบ่งเป็นบทบาท แล้วเขียน Architecture ไว้ใช้ต่อคืนที่ 5

```
Orchestrator → Researcher → Analyst → Writer → Reviewer → คุณ (อนุมัติ)
                                                     └── ตีกลับได้ไม่เกิน 2 รอบ
```

| # | ขั้น | เวลา | หมายเหตุ |
|---|---|---|---|
| 01 | เลือกงานจาก Workshop 7 แล้วชี้ว่าขั้นไหนควรเป็นคนละบทบาท | 3 นาที | ขั้นที่ใช้ทักษะต่างกันชัด ๆ คือรอยต่อที่ควรตัด |
| 02 | กำหนด Role, Input และ Output ของแต่ละตัว | 6 นาที | เขียน Output ก่อน แล้ว Input ของตัวถัดไปจะชัดเอง |
| 03 | วาดเส้นส่งงานและจุดตีกลับให้ครบทุกเส้น | 3 นาที | เส้นที่ไม่มีไฟล์รองรับ คือเส้นที่จะหลุดตอนรันจริง |
| 04 | ลองรันหนึ่งรอบด้วยการสวมบทบาททีละตัว | 3 นาที | ยังไม่ต้องตั้งระบบจริง ขอให้รู้ว่าเส้นไหนขาด |

> จบ 15 นาทีแล้วต้องมีไฟล์ `team.md` หนึ่งไฟล์ ที่บอกได้ว่าใครทำอะไร รับอะไร ส่งอะไร

### เลือกโจทย์ทีมใน 2 นาที

| # | คำถาม | เกณฑ์ |
|---|---|---|
| 01 | ในงานของเรา ขั้นไหนที่ “คนทำ” กับ “คนตรวจ” ควรเป็นคนละคน | ตัวอย่าง · เขียนข้อเสนอแล้วตรวจตัวเลข · ร่างอีเมลแล้วตรวจน้ำเสียง |
| 02 | มีขั้นไหนที่ทำขนานกันได้จริงบ้าง | ถ้าค้นข้อมูลสามแหล่งพร้อมกันได้ นั่นคือ Sub-agent สามตัวที่คุ้มที่สุด |
| 03 | ถ้าตัวใดตัวหนึ่งทำพลาด เราจะรู้ได้จากอะไร | ถ้าตอบไม่ได้ แปลว่ายังไม่มี Gate — ให้เขียนเกณฑ์ตรวจก่อนเริ่ม |

> ตัน 2 นาทีแล้วยังไม่ได้ ให้ใช้โครง Researcher → Writer → Reviewer กับงานของ Workshop 7 ไปเลย

### เทมเพลต — เติมช่องว่างแล้วใช้ได้เลย
ฉบับเต็มอยู่ที่ [`templates/team.md`](../templates/team.md)

```markdown
## ORCHESTRATOR
โจทย์ใหญ่: ________
แตกเป็น ____ บทบาท
ตีกลับได้ไม่เกิน 2 รอบ

## RESEARCHER
รับ: โจทย์ + ขอบเขต
ใช้: ________
ส่ง: research.md + แหล่งที่มา

## WRITER
รับ: research.md
ใช้: Skill ________
ส่ง: draft.md ตามรูปแบบ ____
ห้าม: เพิ่มข้อมูลที่ไม่มีในไฟล์

## REVIEWER
รับ: draft.md + research.md
เกณฑ์: ________
ส่ง: review.md ระบุข้อที่บล็อก
```

ตัวอย่างที่เติมแล้ว · โจทย์ *สรุปคู่แข่ง 3 ราย* · Researcher ใช้ Search + File · Writer ใช้ Skill สรุปหนึ่งหน้า · Reviewer ตรวจว่าทุกตัวเลขมีที่มา

### ทดสอบ Architecture ของตัวเอง · สามรอบ

| รอบ | ทำอะไร | ✓ ผ่านเมื่อ | ✕ ไม่ผ่านแล้วแก้ตรงไหน |
|---|---|---|---|
| 1 · เดินตามเส้นปกติ | สวมบทบาททีละตัว แล้วส่งไฟล์ต่อกันจริงหนึ่งรอบ | ทุกตัวได้ไฟล์ที่ต้องใช้ครบโดยไม่ต้องถามเพิ่ม | ถ้าต้องอธิบายปากเปล่า แปลว่า Handoff ยังไม่ครบ |
| 2 · ให้ Reviewer ตีกลับ | จงใจส่งร่างที่ขาดที่มาไปหนึ่งข้อ แล้วดูว่าระบบทำอะไรต่อ | ตีกลับถูกตัว พร้อมบอกว่าต้องแก้อะไร | ถ้าผ่านฉลุย แปลว่า Gate ยังไม่มีเกณฑ์จริง |
| 3 · ตัดตัวหนึ่งออก | ลองเอา Analyst ออก แล้วดูว่างานยังเดินได้ไหม | งานยังเดินได้ แปลว่าเริ่มด้วยทีมเล็กกว่านี้ก็พอ | ถ้าพังทันที แปลว่าตัวนั้นจำเป็นจริง เก็บไว้ |

> **รอบที่ 3 คือรอบที่ช่วยประหยัดที่สุด** — ทีมเล็กที่เดินได้ ดีกว่าทีมใหญ่ที่ยังไม่เคยรัน
