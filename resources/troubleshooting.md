# ติดปัญหาให้ตรวจตามอาการ
[กลับหน้าแรก](../README.md)

## ปัญหาการติดตั้งและตั้งค่า

| อาการ | ตรวจอะไร | แนวทาง |
|---|---|---|
| หา `hermes` ไม่พบ | Terminal และ environment ที่ติดตั้ง | เปิด shell ใหม่ แล้วตรวจคู่มือติดตั้ง |
| model ไม่ตอบ | provider, บัญชี, เครดิต, ข้อความผิดพลาด | ตรวจบัญชีส่วนตัว **ไม่แปะ key ใน Issue** |
| อ่านไฟล์ไม่พบ | current directory และตำแหน่ง repo | เปิด Terminal ในโฟลเดอร์ที่แตก ZIP |
| ใช้ tool ไม่ได้ | tool ถูกเปิดหรือไม่ และ credential | ทดสอบทีละ integration |

## ปัญหาระหว่าง Workshop

| อาการ | คืนที่เจอ | ทางแก้ |
|---|---|---|
| ไม่จำเรื่องเดิม | 2 | แยกการ resume (`--continue`) ออกจาก memory ข้าม session · ตรวจว่า `MEMORY.md` ถูกอ่านจริง |
| Agent ตอบว่าทำเสร็จแล้ว แต่ไม่มีไฟล์ | 3 | สั่งให้ `list` โฟลเดอร์แล้วอ่านไฟล์กลับมาให้ดู |
| เรียกเครื่องมือเดิมวนซ้ำไม่จบ | 3 | หยุดแล้วถามว่า “ตอนนี้ติดอะไร” ให้สรุปสถานะก่อนไปต่อ |
| ขอสิทธิ์ทุกคำสั่งจนทำงานไม่ลื่น | 3 | อนุญาตล่วงหน้าเฉพาะคำสั่งอ่านอย่างเดียว |
| Skill เขียนแล้วแต่เรียกไม่ติด | 3 | แก้ `description` ให้มีคำที่เราพิมพ์จริง ไม่ใช่แก้ขั้นตอน |
| Agent ข้ามขั้นแล้วไปตอบตอนจบเลย | 4 | สั่งให้ส่งผลลัพธ์ของแต่ละขั้นเป็นไฟล์ แล้วรอ ok ก่อนเดินต่อ |
| Context เต็มแล้วลืมโจทย์ | 2, 4 | ให้เขียนผลลงไฟล์ แล้วขั้นถัดไปอ่านจากไฟล์ ไม่ใช่จากแชท |
| Reviewer ผ่านทุกอย่างไม่ค้านอะไรเลย | 4 | ให้เกณฑ์ตรวจเป็นข้อ ๆ และบังคับให้รายงานข้อที่ไม่ผ่านอย่างน้อยหนึ่งข้อ |
| Agent ทำตามคำสั่งที่อยู่นอกขอบเขต | 5 | ย้ายข้อห้ามขึ้นต้นไฟล์ และเขียนเป็นประโยคสั่ง ไม่ใช่คำแนะนำ |
| รันได้ดีเฉพาะตอนที่เราอยู่ด้วย | 5 | บันทึกทุกครั้งที่เราแทรก แล้วเปลี่ยนสิ่งที่แทรกให้เป็นบรรทัดในไฟล์ |
| ผลลัพธ์ดูดีแต่ผิด | ทุกคืน | เทียบกับข้อมูลต้นทาง · สุ่มตรวจย้อนกลับสองข้อ |
