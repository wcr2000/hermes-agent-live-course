## Workshop 3 · Session Experiment
**20:30 – 21:05 น. · 35 นาที**

เป้าหมายคือ **เห็นด้วยตาตัวเอง** ว่า Session เก็บอะไรไว้ และไม่เก็บอะไรไว้

### ขั้นตอนการทดลอง

| # | ทำอะไร |
|---|---|
| 01 | สร้าง Session ใหม่ |
| 02 | ให้ข้อมูลสำคัญกับ Agent — ชื่อ บทบาท และรูปแบบงานที่ต้องการ |
| 03 | ปิด Session |
| 04 | เปิด Session ใหม่ แล้วถามข้อมูลเดิมซ้ำ |
| 05 | บันทึกว่าอะไรถูกจำ และอะไรหายไป |

### Session A — วางทีละบรรทัด

```text
ผมชื่อ [ชื่อของคุณ] เป็น [ตำแหน่ง] ตอบเป็นภาษาไทย สั้น ๆ
```

```text
ช่วยร่าง [งานจริงสั้น ๆ ของคุณ เช่น อีเมลแจ้งทีมเรื่อง ________]
```

**ต้องเห็น** · มันร่างให้เลย เป็นภาษาไทย สั้น ตามที่บอกไว้

### ปิดแล้วเปิดใหม่

```bash
# ออกจาก CLI แล้วเปิดใหม่ (ไม่ใช่ --continue)
hermes
```

> `hermes --continue` คือการเปิด Session เดิมต่อ — ใช้ตอนเปรียบเทียบในขั้นที่ 5 ได้ แต่ **อย่าใช้ในขั้นที่ 4** ไม่งั้นจะไม่เห็นผลของการทดลอง

### Session B — ถามคำถามเดียวกัน

```text
ช่วยร่าง [งานเดิมเป๊ะ ๆ ที่เพิ่งสั่งไปใน Session A]
```

**สิ่งที่มักจะเกิด** · มันถามกลับว่าทีมคือใคร อยากได้น้ำเสียงแบบไหน หรือตอบกลับมาเป็นภาษาอังกฤษ
ความสามารถยังอยู่ครบ — สิ่งที่หายคือ **บริบทเรื่องเรา**

### บันทึกผล

สร้างไฟล์ `session-experiment.md` แล้วเขียนสามหัวข้อ

```markdown
## สิ่งที่ Agent ยังทำได้ใน Session B
## สิ่งที่หายไป
## สิ่งที่เราอยากให้มันจำได้ถาวร   ← รายการนี้คือวัตถุดิบของ Workshop 4
```

### Session ไม่ใช่ Memory

| | Session | Memory |
|---|---|---|
| ผูกกับอะไร | งานหนึ่งเรื่อง | ตัวเราและโปรเจกต์ |
| อายุ | เกิดเมื่อเริ่มงาน จบเมื่อปิดงาน | อยู่ต่อข้าม Session ทุกอัน |
| เก็บอะไร | ประวัติและสถานะของงาน | ข้อเท็จจริงที่ใช้ซ้ำ |

## Workshop 4 · Build Your AI Memory
**21:40 – 22:00 น. · 20 นาที**

### ห้าขั้น

| # | ทำอะไร |
|---|---|
| 01 | เขียน User Memory — ใครคือเรา ทำงานอะไร และอยากได้ผลลัพธ์แบบไหน |
| 02 | เขียน Project Memory — โปรเจกต์ที่เลือกมีบริบทและข้อตกลงอะไร |
| 03 | คัดให้เหลือเฉพาะข้อที่จริงข้ามวัน ตัดที่เหลือออก |
| 04 | ปิด Agent แล้วเปิดใหม่ สั่งงานเดิมโดยไม่บอกบริบทซ้ำ |
| 05 | ดูว่าผลลัพธ์ต่างจากก่อนมี Memory อย่างไร แล้วแก้ Memory ให้แคบลง |

### เทมเพลต — เติมช่องว่างได้เลย

เขียนให้เสร็จใน 5 นาที แล้วค่อยตัดทีหลัง — สั้นเกินแก้ง่ายกว่ายาวเกิน
ฉบับเต็มอยู่ที่ [`templates/MEMORY.md`](../templates/MEMORY.md)

```markdown
## USER MEMORY
ผมชื่อ ________ ทำงานเป็น ________
ในทีม ________ ดูแลเรื่อง ________
ตอบเป็นภาษา ________ ความยาวประมาณ ________
รูปแบบผลลัพธ์ที่ชอบ ________
สิ่งที่ห้ามทำ ________

## PROJECT MEMORY
โปรเจกต์นี้คือ ________
คำศัพท์เฉพาะ ________ แปลว่า ________
ไฟล์หรือโฟลเดอร์สำคัญ ________
ข้อตกลงของทีม ________
ข้อห้าม ________
```

### ตัวอย่างที่เขียนเสร็จแล้ว

```markdown
## USER MEMORY
ชื่อ ต้น · Data Engineer ทีม Analytics
ตอบเป็นภาษาไทย กระชับ ไม่ต้องเกริ่น
โค้ดตัวอย่างขอเป็น Python 3.11
สรุปยาว ๆ ขอ bullet ไม่เกิน 7 ข้อ

## PROJECT MEMORY
โปรเจกต์ retail-sync — ส่งข้อมูลจาก HQ ไปสาขา
"outlet" = สาขา · "HQ" = สำนักงานใหญ่
โค้ดอยู่ใน src/ เทสอยู่ใน tests/
ห้ามแก้ไฟล์ใน legacy/ โดยไม่ถามก่อน

## PROCEDURAL MEMORY
เวลาสรุปประชุม ให้เรียงแบบนี้เสมอ
1. หัวข้อ  2. ข้อตกลง  3. ใครทำอะไร ภายในเมื่อไร  4. สิ่งที่ค้าง
ส่งเป็น Markdown ทุกครั้ง
```

> ทั้งสามส่วนรวมกันไม่ควรยาวกว่าหนึ่งหน้า — ยาวกว่านั้นแปลว่ามีของที่ไม่จริงข้ามวันปนอยู่

### ทดสอบ

ปิด Agent แล้วเปิดใหม่ สั่งงานเดิมโดย **ไม่บอกบริบทซ้ำ**
ถ้ายังต้องอธิบายตัวเองอีกรอบ แปลว่า Memory ยังไม่พอ — กลับไปเติมแล้วลองใหม่
