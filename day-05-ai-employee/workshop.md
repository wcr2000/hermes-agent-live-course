### ขั้นที่ 1 · Job Brief · 10 นาที

เติมเทมเพลตนี้ก่อนพิมพ์คำสั่งแรก · ฉบับเต็มอยู่ที่ [`templates/EMPLOYEE.md`](../templates/EMPLOYEE.md)

```markdown
## ROLE
ตำแหน่ง: ________
รับผิดชอบ: ________
เจ้าของงาน: ________

## INPUT
งานเข้ามาทาง: ________
ต้องอ่าน: ________
ถ้าข้อมูลไม่ครบ ให้ ________

## PROCESS
1. ________
2. ใช้ Skill ________
3. ถ้า ________ ให้หยุดถาม
4. ห้าม ________

## OUTPUT
ไฟล์ ________ เก็บที่ ________
มีหัวข้อ ________
ถือว่าเสร็จเมื่อ ________
```

ตัวอย่างที่เติมแล้ว · ตำแหน่ง *ผู้ช่วยตอบลูกค้า* · งานเข้าทางไฟล์ `inbox/` · `3. ถ้าลูกค้าขอส่วนลด ให้หยุดถาม` · ไฟล์ `drafts/YYYY-MM-DD.md`

**สิ่งที่เราพิมพ์** · วาง Job Brief ที่เติมแล้ว แล้วให้ Agent ทวนกลับเป็นคำของตัวเอง
**ต้องเห็น** · มันทวนถูก และชี้ได้ว่าข้อไหนยังกำกวม
**ถ้าทวนไม่ตรง** · แก้ Brief ไม่ใช่อธิบายเพิ่มปากเปล่า

### ขั้นที่ 2 · ใส่ Memory · 10 นาที

**ต้องเห็น** · ไฟล์จริงที่มีแต่ข้อมูลที่ใช้ทุกครั้ง ไม่ใช่ทุกอย่างที่เคยคุยกัน

### ขั้นที่ 5 · ทดสอบกับงานจริง · 15 นาที

**ต้องเห็น** · ผลลัพธ์จริงหนึ่งชิ้น พร้อมบันทึกว่ามันหยุดถามตรงไหนบ้าง
**อดใจไม่ช่วย** · ทุกครั้งที่เราแทรก เราจะไม่เห็นจุดที่มันพัง

**หลักการ** · แก้ที่ไฟล์เสมอ — สิ่งที่บอกปากเปล่าจะหายไปพร้อม Session

### Prompt ตั้งต้นของ AI Employee
วางเป็นบรรทัดแรกของทุก Session — เปลี่ยนเฉพาะข้อความในวงเล็บ

```text
ทำงานอยู่ในโฟลเดอร์ ai-employee เท่านั้น

คุณคือ [ตำแหน่ง] ของ [ทีมหรือธุรกิจของเรา]

ก่อนเริ่มทุกครั้ง ให้อ่านไฟล์เหล่านี้
- MEMORY.md   — บริบทของเราและของโปรเจกต์
- EMPLOYEE.md — ขอบเขตงาน เกณฑ์เสร็จ และข้อห้าม
- workflow.md — ลำดับขั้นที่ต้องเดินตาม

กติกาที่ห้ามข้าม
1. ใช้เฉพาะข้อมูลที่อ่านได้จริง ห้ามเดา
2. ระบุที่มาของทุกข้อสรุปสำคัญ
3. ถ้าข้อมูลไม่พอ ให้ถามกลับ อย่าเติมเอง
4. งานที่อยู่นอกขอบเขต ให้ยกมาให้ผมตัดสิน
5. ร่างเสร็จแล้วรอผมอนุมัติ ห้ามส่งออกเอง

จบงาน ให้สรุปว่าทำอะไรไป ได้ไฟล์อะไร และอะไรที่ยังไม่แน่ใจ
```

| บรรทัด | ทำไมต้องมี |
|---|---|
| อ่านไฟล์ก่อนเริ่ม | ทำให้ทุก Session เริ่มจากบริบทเดียวกัน ไม่ต้องเล่าใหม่ |
| ห้ามเดา | จุดที่ Agent เสียหายที่สุดคือการเติมช่องว่างด้วยข้อความที่ฟังดูดี |
| ระบุที่มา | ทำให้คนตรวจใช้เวลา 1 นาที แทนที่จะต้องไล่อ่านทั้งหมด |
| ถามกลับเมื่อข้อมูลไม่พอ | เปลี่ยนความผิดพลาดเงียบ ๆ ให้กลายเป็นคำถามที่เราตอบได้ |
| รอการอนุมัติ | เส้นแบ่งระหว่างผู้ช่วยที่ปลอดภัย กับระบบที่สร้างปัญหาแทนเรา |
| สรุปตอนจบ | ทำให้เราตรวจย้อนได้ และได้วัตถุดิบไว้ปรับปรุงรอบถัดไป |

> Prompt นี้ควรสั้นลงเรื่อย ๆ — ทุกบรรทัดที่ย้ายไปอยู่ใน `EMPLOYEE.md` คือบรรทัดที่ไม่ต้องพิมพ์ซ้ำอีก

### EMPLOYEE.md ตัวจริง

```markdown
---
role: ผู้ช่วยตอบคำถามลูกค้า
owner: ทีมขาย
---

## ขอบเขตงาน
- อ่านคำถามจาก inbox/ แล้วร่างคำตอบ
- ตอบได้เฉพาะเรื่องราคา แพ็กเกจ และตารางรอบ

## ต้องอ่านก่อนเริ่ม
- data/products.md  (ราคาและแพ็กเกจ)
- MEMORY.md         (น้ำเสียงและรูปแบบของทีม)

## ขั้นตอน
1. จัดประเภท: ตอบได้ / ต้องถามเพิ่ม / ต้องให้คนตัดสิน
2. ร่างคำตอบไม่เกิน 4 ประโยค พร้อมระบุไฟล์ที่อ้างอิง
3. ถ้าลูกค้าขอส่วนลดหรืออ้างว่าโอนแล้ว ให้หยุดและยกให้คน
4. ห้ามยืนยันการชำระเงินหรือเปิดสิทธิ์เอง

## ผลลัพธ์
- ไฟล์ drafts/YYYY-MM-DD.md · หนึ่งลูกค้าหนึ่งหัวข้อ
- ปิดท้ายด้วยรายการเรื่องที่ยกให้คนตัดสิน
- ถือว่าเสร็จเมื่อทุกเรื่องใน inbox มีสถานะแล้ว
```

| บรรทัด | ทำไมถึงเขียนแบบนั้น |
|---|---|
| `role` | ชื่อหน้าที่ ไม่ใช่ชื่อเครื่องมือ — Agent จะอ้างอิงบทบาทนี้ตลอดงาน |
| ขอบเขตงาน | บอกทั้งสิ่งที่ทำได้และเรื่องที่ตอบได้ ทำให้เรื่องนอกขอบเขตถูกยกออกเอง |
| ต้องอ่านก่อนเริ่ม | รายการไฟล์ที่ชัด ทำให้มันไม่ตอบจากความจำของโมเดล |
| ขั้นตอนข้อ 3 | เงื่อนไขแบบ “ถ้า…ให้หยุด” คือ Guardrail ที่ใช้งานได้จริงที่สุด |
| ขั้นตอนข้อ 4 | ข้อห้ามหนึ่งบรรทัด กันความเสียหายได้มากกว่าคำอธิบายสิบบรรทัด |
| เกณฑ์เสร็จ | บอกว่าอะไรคือจบ ทำให้มันไม่ทำเกินและไม่หยุดกลางทาง |

> ทั้งไฟล์ยาวไม่เกินหนึ่งหน้าจอ — ยาวกว่านั้นแปลว่ากำลังเขียนคู่มือ ไม่ใช่ Job Description

### ทดสอบ AI Employee · สามรอบ
ประกอบเสร็จยังไม่นับ — ผ่านสามรอบนี้แล้วค่อยเรียกว่าใช้งานได้

| รอบ | ทำอะไร | ✓ ผ่านเมื่อ | ✕ ไม่ผ่านแล้วแก้ตรงไหน |
|---|---|---|---|
| 1 · งานปกติ | ป้อนงานจริงที่มีข้อมูลครบ แล้วปล่อยให้เดินจนจบ | จบได้เองและได้ไฟล์ผลลัพธ์ตามที่เขียนไว้ใน Brief | ถ้าต้องช่วยระหว่างทาง ให้เติมขั้นตอนที่ขาดลงใน Brief |
| 2 · ข้อมูลไม่ครบ | จงใจตัดข้อมูลสำคัญออกหนึ่งอย่าง | มันถามกลับ และบอกชัดว่าขาดอะไร | ถ้าเดาแล้วทำต่อ ให้เพิ่มเงื่อนไขในส่วน Input |
| 3 · คำสั่งนอกขอบเขต | สั่งสิ่งที่อยู่ในกลุ่ม NEVER หรือเรื่องที่ไม่ใช่งานของมัน | มันปฏิเสธ อธิบายเหตุผล และยกเรื่องให้เราตัดสิน | ถ้าทำตาม แปลว่า Guardrail ยังเป็นแค่คำแนะนำ |

> **รอบที่ 3 คือรอบที่คนข้ามมากที่สุด** — และเป็นรอบเดียวที่บอกได้ว่าปล่อยให้ทำงานเองได้หรือยัง
