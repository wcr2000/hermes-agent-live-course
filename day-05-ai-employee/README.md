## Guardrail · แบ่งสิทธิ์ของพนักงาน AI เป็นสามระดับ
เขียนสามระดับนี้ลงใน `EMPLOYEE.md` ตั้งแต่วันแรก — ไม่ใช่รอให้เกิดเรื่องก่อน

| ALLOW · ทำได้เอง | ASK · ถามก่อน | NEVER · ห้ามเด็ดขาด |
|---|---|---|
| อ่านไฟล์ในโฟลเดอร์งาน | เขียนทับไฟล์ที่มีอยู่แล้ว | ส่งข้อความออกหาลูกค้าเอง |
| ค้นข้อมูลสาธารณะ | เรียก API ที่เปลี่ยนข้อมูล | ยืนยันการชำระเงินหรือเปิดสิทธิ์ |
| ร่างงานลงโฟลเดอร์ `drafts` | ให้ข้อมูลที่เป็นการยืนยันกับลูกค้า | ให้ส่วนลดหรือสัญญาที่ผูกพัน |
| สรุปสถานะให้เราอ่าน | ทำงานที่อยู่นอกขอบเขตใน Brief | แตะระบบ Production โดยตรง |
| *พลาดแล้วไม่เสียหาย · ย้อนได้ทันที* | *ย้อนได้ แต่ต้องมีคนรู้ตัวก่อน* | *พลาดครั้งเดียวย้อนไม่ได้* |

> เขียนสามระดับนี้เป็นข้อ ๆ ในไฟล์ แล้ว **ทดสอบทุกข้อในกลุ่ม NEVER อย่างน้อยหนึ่งครั้ง**

## Memory ที่ AI Employee ต้องมี

1. **เรื่องของเรา** — ใครใช้ Agent ตัวนี้ และคาดหวังอะไร · น้ำเสียง ภาษา ความยาวที่ชอบ
2. **เรื่องของงาน** — ข้อมูลตั้งต้นที่ไม่เปลี่ยนบ่อย · ชื่อทีม สินค้า ราคา ข้อตกลง และสิ่งที่ยังไม่มีข้อมูล
3. **เรื่องของวิธีทำงาน** — รูปแบบไฟล์ ชื่อโฟลเดอร์ และสิ่งที่เคยทำผิดแล้วไม่อยากให้ผิดซ้ำ
4. **สิ่งที่ไม่ควรอยู่ใน Memory** — รหัสผ่าน ข้อมูลลูกค้ารายบุคคล และเรื่องที่ใช้ครั้งเดียวแล้วจบ

> ทดสอบง่าย ๆ — ปิดแล้วเปิดใหม่ ถ้ามันยังทำงานได้เหมือนเดิม แปลว่า Memory ครบแล้ว

## Ability · ให้ความสามารถเท่าที่งานต้องใช้
เปิดทุกอย่างไว้ก่อนไม่ได้ทำให้เก่งขึ้น — ทำให้ตรวจยากขึ้นและพลาดแรงขึ้น

| | ให้อะไร | หลักการเลือก |
|---|---|---|
| **Tools** | อ่าน/เขียนไฟล์ในโฟลเดอร์งาน · ค้นข้อมูล · เรียก API ที่อนุญาต | เลือกจากขั้นตอนที่เขียนไว้จริง ถ้าไม่มีขั้นไหนใช้ ก็ยังไม่ต้องเปิด |
| **Skills** | `SKILL.md` จากคืนที่ 3 · Playbook ของทีม · เงื่อนไขเฉพาะงาน | Skill คือส่วนที่ทำให้ผลลัพธ์หน้าตาเหมือนเดิมทุกครั้ง |
| **Sub-agents** | Researcher ค้นข้อมูล · Reviewer ตรวจงาน | ใส่เมื่อจำเป็นเท่านั้น — เริ่มด้วยตัวเดียวก่อน |

> ทุกความสามารถที่เปิด ต้องตอบได้ว่าใช้ในขั้นไหนของ Workflow — ถ้าตอบไม่ได้ ให้ปิดไว้ก่อน

## เขียน Job Description ให้ตรวจได้

| เขียนแบบนี้ Agent ตีความเอง | เขียนแบบนี้ตรวจได้ |
|---|---|
| “ตอบลูกค้าให้ดี” | ร่างไม่เกิน 4 ประโยค ระบุไฟล์ที่อ้างอิง แล้วรอคนอนุมัติก่อนส่ง |
| “ใช้ข้อมูลที่ถูกต้อง” | ใช้เฉพาะข้อมูลใน `data/` · ถ้าไม่มีให้เขียนว่า “ยังไม่มีข้อมูล” |
| “ระวังเรื่องละเอียดอ่อน” | เรื่องส่วนลด การเงิน และข้อมูลส่วนบุคคล ให้หยุดและยกให้คน |
| “ทำงานให้เสร็จ” | ถือว่าเสร็จเมื่อทุกเรื่องใน `inbox` มีสถานะ และมีไฟล์ร่างครบทุกเรื่อง |
| “รายงานผลด้วย” | ปิดท้ายทุกรอบด้วยจำนวนเรื่องที่ทำ เรื่องที่ยกให้คน และสิ่งที่ยังไม่แน่ใจ |

2. **จดทุกครั้งที่เราต้องเข้าไปแก้ให้มัน** — รายการนี้คือ backlog ของการปรับปรุง
3. **แก้ที่ไฟล์เสมอ ไม่ใช่บอกปากเปล่า** — ทุกครั้งที่อธิบายซ้ำ คือหลักฐานว่ามีบรรทัดที่ยังขาด
4. **ตั้งรอบทบทวนสั้น ๆ เดือนละครั้ง** — Agent ที่ไม่ถูกแก้จะกลายเป็นของผิดภายในไม่กี่เดือน

> เป้าหมายของสัปดาห์แรกคือ **ใช้ให้ครบเจ็ดวัน** ไม่ใช่ทำให้สมบูรณ์แบบ

### พร้อมขยาย หรือยังไม่ควร

| ✓ สัญญาณว่าพร้อมขยาย | ✕ สัญญาณว่ายังไม่ควร |
|---|---|
| รันกับงานจริงมาแล้วอย่างน้อยสิบรอบ | ยังรันแค่ไม่กี่รอบและมีเราคอยดูตลอด |
| ผลตรวจย้อนหลังนิ่ง ไม่มีของที่หลุดออกไป | ยังเจอข้อผิดพลาดใหม่ทุกสัปดาห์ |
| มีคนอื่นในทีมใช้ได้โดยไม่ต้องถามเรา | มีเราคนเดียวที่ใช้เป็น |
| มีวิธีหยุดและกู้คืนที่ทดสอบแล้ว | ยังไม่เคยลองหยุดกลางทางเลย |
| รู้ต้นทุนต่อหนึ่งงานและยอมรับได้ | ยังไม่เคยดูว่าใช้ไปเท่าไร |
